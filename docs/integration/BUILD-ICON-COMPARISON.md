# Build & Icon Comparison

## Cursor build method

- `electron-builder` **^25.1.8** with config in `package.json` → `build`
- Windows target: NSIS x64
- `win.icon` / NSIS installer/uninstaller/header icons → `build/Program-Icon.ico`
- Brand assets generated by `scripts/generate-brand-assets.mjs` / `branding-engine.mjs`
- **`win.signAndEditExecutable`: `false`** (set during Windows-compat work so Linux CI builds do not require Wine/rcedit)
- `BrowserWindow` **does not** set `icon:` explicitly
- Artifact: `HijamaManagement-Setup-${version}.exe`
- `executableName`: `Hijama Management System`

## Codex build method

- `electron-builder` **^26.15.0**
- Same icon paths (`build/Program-Icon.ico`) and NSIS icon fields
- **`win.signAndEditExecutable`: `true`** → rcedit embeds icon + version metadata into EXE
- `npmRebuild: false` in build config
- Includes `renderer/**/*`, `security/**/*`, `update-client.js` in `files`
- Same product naming / publisher trademarks

## Cursor icon behavior

- ICO present and valid; sizes **16, 32, 48, 64, 128, 256** (no 24)
- Installer BMP/sidebar assets present
- With `signAndEditExecutable: false`, Windows **unpacked EXE / taskbar / shortcuts** often show **default Electron icon** even when installer UI icons are correct
- Window title-bar icon not forced via `BrowserWindow.icon`

## Codex icon behavior

- **Identical ICO bytes** to Cursor (SHA256 match)
- With `signAndEditExecutable: true`, EXE resource typically shows Program icon → Start Menu / Desktop / Taskbar / ARP inherit correctly when built on Windows

## Root cause of Electron default icon

**Not a missing or corrupt ICO.**  
Primary cause: Cursor disables `signAndEditExecutable`, so electron-builder **does not run rcedit** to write the ICO into the EXE. Secondary gap: no explicit `BrowserWindow({ icon })`.

## Recommended final configuration

1. Keep Cursor electron-builder **25.1.8** and Electron **33.2.0** for Hybrid RC.
2. Keep `signAndEditExecutable: false` — enabling it pulls `winCodeSign`, which fails on many Windows machines with:
   `Cannot create symbolic link : A required privilege is not held by the client` (darwin dylib symlinks inside the archive).
3. Embed the EXE icon via **`afterPack` + `resedit`** (`scripts/electron-builder-after-pack.cjs`) — no winCodeSign, no admin/Developer Mode required for symlinks.
4. Set `BrowserWindow` `icon` to `build/Program-Icon.ico` for window/taskbar fallback.
5. Include **24×24** in ICO generation sizes in `branding-engine.mjs`.
6. Set top-level `build.icon` = `build/Program-Icon.ico`.
7. **Do not** port Codex Electron 39 solely for icons.
8. Authenticode (K-32) remains separate from icon embedding.
